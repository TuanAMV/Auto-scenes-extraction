# 视频向量化逻辑（Indexer + P模式）

更新时间：2026-02-16
代码依据：`Cut_DetectScene/indexer_app.py`、`Cut_DetectScene/pipeline_app.py`、`Cut_DetectScene/A_coreUtils/embedding/embedding_model.py`

## 1. 视频向量化入口

### 1.1 独立脚本入口（`indexer_app.py`）

1. 启动脚本执行 `main()`（`indexer_app.py:21`）。
2. 先导入向量化核心函数：
   - `create_video_index`
   - `batch_create_video_index`
3. 导入失败时直接 `sys.exit(1)`（`indexer_app.py:13-18`）。

执行步骤：

1. 在 `main()` 内定义输入/输出目录与 `PARAMETERS`（`indexer_app.py:29-88`）。
2. 检查 `INPUT_DIRECTORY` 是否存在，不存在直接退出（`indexer_app.py:96-98`）。
3. 创建输出目录（`indexer_app.py:101`）。
4. 自动判断输入模式（`indexer_app.py:103-106`）：
   - 当前目录含视频文件 → 单目录索引模式
   - 当前目录含子文件夹 → 批量子目录索引模式
5. 分支调用：
   - 单目录：`create_video_index([INPUT_DIRECTORY], OUTPUT_DIRECTORY, **PARAMETERS)`（`indexer_app.py:108-114`）
   - 批量目录：`batch_create_video_index(INPUT_DIRECTORY, OUTPUT_DIRECTORY, **PARAMETERS)`（`indexer_app.py:116-122`）
6. 按成功状态返回退出码：成功 `0`，失败 `1`（`indexer_app.py:133`）。

### 1.2 Pipeline Web 入口（`pipeline_app.py`）

1. 前端调用 `GET /run_pipeline_stream`，后端在子进程中执行 `run_pipeline_thread(config)`。
2. 当 `run_indexer=True` 时，调用 `run_indexer_with_config(config)`（`pipeline_app.py:338-434`）。
3. 从 `config.get('indexer', {})` 读取索引配置，仅允许名称包含 `clip` 的模型（`_is_clip_model_name()`，`pipeline_app.py:193-196`）。
4. 构建参数字典，采用"仅传预设中明确存在的参数"策略（`pipeline_app.py:362-375`）。
5. 自动判断输入模式后调用 `create_video_index()` 或 `batch_create_video_index()`。

### 1.3 参数映射

| 参数 | indexer_app 默认值 | pipeline_app 默认值 | 作用 |
| --- | --- | --- | --- |
| `model_name` | `openai-clip-vit-large-patch14` | `qihoo360_fg-clip2-base` | 向量模型名（可自动从 models 目录解析） |
| `model_type` | `auto` | `auto` | 模型类型自动检测（`clip`/`fgclip2`） |
| `truncate_dim` | `None` | `None`（预设中有值时转 `int`） | 向量截断维度 |
| `output_resolution` | `'256'` | 预设值 | 抽帧分辨率（短边像素） |
| `batch_size` | `512` | 预设值 | GPU 推理批处理大小 |
| `workers` | `2` | 预设值 | 异步写入 Lance 的并行线程数 |
| `io_workers` | `8` | 预设值 | I/O 并发线程数，用于读取帧图片进入 PIL |
| `cosine_similarity_threshold` | `0.82` | 预设值 | 场景切换相似度阈值（0.0~1.0，越大越敏感） |
| `brightness_threshold` | `15` | 预设值 | 黑场判定亮度阈值（0-255），`0` 或 `None` 禁用 |
| `black_pixel_ratio` | `98` | 预设值 | 黑像素占比阈值（0-100） |
| `sample_interval` | `3` | 预设值 | 抽样间隔（每 N 帧取一帧） |
| `min_scene_length` | `7` | 预设值 | 最小场景长度（帧数） |
| `localmax_order` | `1` | 预设值 | 局部极大值检测邻域窗口 |
| `resume_processing` | `False` | 预设值 | 是否增量处理（跳过已索引的视频） |
| `use_fp16` | `True` | 预设值 | 是否使用 FP16 半精度推理 |

## 2. 核心向量化流程（`embedding_model.py`）

### 2.1 模型加载（`EmbeddingModelProcessor`）

`EmbeddingModelProcessor`（`embedding_model.py`）负责加载 CLIP/FG-CLIP2 模型并执行向量化：

1. **模型路径解析**：优先使用绝对路径，否则在 `models/` 目录下查找。
2. **模型类型检测**：`detect_model_type()` 按以下顺序检测：
   - 文件夹名包含 `fg-clip2` / `fg_clip2` / `fgclip2` → `fgclip2`
   - 存在 `open_clip_config.json` → `clip`（open_clip 格式）
   - 存在 `config.json` 且 `architectures` 含 CLIP → `clip`（transformers 格式）
   - 否则 → `auto`
3. **FP16 支持**：`use_fp16=True` 时模型以半精度运行，节省约 50% 显存。
4. **离线模式**：启动时设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，完全离线加载。

### 2.2 视频处理流水线

`process_video()`（`embedding_model.py`）对单个视频执行以下流水线：

1. **帧提取**（`FrameExtractorThread`）：
   - 使用 FFmpeg 按 `sample_interval` 间隔抽帧
   - 输出分辨率由 `output_resolution` 控制（短边缩放）
   - 帧图片保存到 `temp/` 临时目录

2. **向量化**（`VectorizerThread`）：
   - 双缓冲流水线：I/O 加载与 GPU 推理并行执行
   - 多线程并行加载帧图片（`io_workers` 个线程）
   - 预加载机制：当前批次 GPU 推理时，下一批次已在 I/O 加载
   - 黑帧检测：在图片加载时同步检测（`brightness_threshold` + `black_pixel_ratio`），无额外 I/O 开销
   - 批量 GPU 推理：每 `batch_size` 帧一批送入模型

3. **场景边界检测**（`SceneBoundaryDetector.find_scene_boundaries()`）：
   - 计算相邻帧向量的余弦相似度
   - 相似度低于 `cosine_similarity_threshold` 的位置标记为场景边界
   - 使用 `localmax_order` 窗口做局部极大值检测

4. **短场景合并**：
   - 当场景帧数 < `min_scene_length` 时，与相邻最相似的场景合并

5. **三元组特征提取**：
   - 每个场景提取首帧、中间帧、尾帧的特征向量（3帧）
   - 特征向量经 L2 归一化后存储

### 2.3 索引存储（Lance 格式）

`create_video_index()`（`embedding_model.py:1100-1221`）：

1. **索引文件命名**：`{视频源名}_{模型名}.lance`（如 `MyAnime_qihoo360_fg-clip2-base.lance`）。
2. **增量处理**：`resume_processing=True` 时，通过 `get_indexed_video_paths()` 检查已索引的视频路径，跳过已处理的视频。
3. **异步写入**：使用 `AsyncLanceWriter` 异步写入 Lance 索引，避免阻塞 GPU 推理。
4. **数据格式**：每行包含视频路径、起始帧、结束帧、FPS、归一化后的特征向量（3帧×维度）。
5. **临时文件清理**：处理完成后清理 `temp/` 目录。

### 2.4 批量处理

`batch_create_video_index()`（`embedding_model.py:1224-1264`）：

1. 扫描输入目录下的所有子文件夹。
2. 逐个子文件夹调用 `create_video_index()`。
3. 统计成功/失败数量，处理完成后清理临时文件。

## 3. 搜索引擎（`SemanticSearchEngine`）

`SemanticSearchEngine`（`embedding_model.py:957-1098`）用于 `text_search.py` 的文本搜索：

1. **Lance 直读**：`_load_features_from_lance()` 直接从 Lance 索引读取特征向量，无需 NPZ 缓存层。
2. **文本编码**：将查询文本通过 CLIP 模型编码为向量。
3. **相似度计算**：使用模型原生 `logit_scale`（默认 100.0）缩放余弦相似度。
4. **结果返回**：返回超过阈值的匹配场景列表，包含视频路径、帧区间、相似度分数。
